# 코토바 v0.3.2 · APK 내장 한 획씩 쓰기

현재는 내부 테스트 버전입니다. Google Play 정식 제출 승인이 아닙니다.

## 이번 변경

손글씨 모델 다운로드를 제거했습니다. APK에 획 데이터와 판정 알고리즘이 들어 있으며, 한 획을 그어 손을 떼면 시작/끝 위치, 방향, 경로, 길이와 획순을 비교합니다. 허용 범위 안이면 170ms 동안 올바른 위치로 보정합니다. 맞은 획은 남기고 틀린 획만 재시도합니다. 탭, 무작위 낙서, 역방향, 너무 짧은 획은 통과하지 않습니다.

따라 쓰기는 다음 획과 초록 시작점/방향을 표시합니다. 기억해서 쓰는 시험은 안내를 숨기며, 잘못 그은 뒤 완성한 단어는 재시험 대상으로 기록합니다. 사용자 자가평가 버튼이나 정답을 무조건 인정하는 우회 경로는 없습니다. 자유 필기 OCR이 아닌 **정해진 한자·가나의 획순/모양 학습 판정**입니다.

기존 N5~N1 8,451개 급수별 어휘 항목에 쓰이는 **2,244문자 / 22,615획**을 APK에 포함합니다. 손글씨 데이터 누락 시 빌드가 실패합니다. ML Kit 의존성과 Android 앱의 INTERNET 권한을 제거했습니다. 첫 실행에도 모델을 다운로드하지 않습니다. 일본어 음성은 별도 기기 TTS 엔진에 따르므로 손글씨의 오프라인 보장과 구분합니다.

한 획 취소, 현재 글자 다시 쓰기, 완료 획 재생, 중간 획 저장/복원, 히라가나 ON/OFF를 유지합니다. 예전 자유 필기 형태의 미완료 그림은 새 획순 판정으로 인정하지 않고 해당 글자부터 다시 씁니다. 기존 단어/복습 기록은 삭제하지 않습니다.

Android WebView에 직접 padding을 넣던 방식에서, 부모 FrameLayout을 시스템 영역 안으로 배치하도록 변경했습니다. 고정 하단 버튼이 시스템 내비게이션에 덮이지 않도록 조정합니다.

## 빌드

```sh
# 최초 v0.3.1 체크아웃에만 필요한 소스 마이그레이션. 이미 변경된 소스는 다시 패치하지 않음.
python3 jlpt-quest/scripts/upgrade-snap.py
cd jlpt-quest
npm run build
npm test
npm run android:sync
cd ../kotoba-android
gradle :app:assembleDebug :app:lintDebug
```

`build`의 다운로드는 개발 PC/CI에서 라이선스가 있는 공개 자료를 고정 커밋으로 가져오는 단계입니다. **설치된 앱에서는 이 다운로드 코드가 실행되지 않습니다.** CI는 검증 후 생성된 runtime 소스와 획 팩을 같은 feature 브랜치에 저장합니다. 기존 main이나 공개 사이트는 바꾸지 않습니다.

## 검증 방법

- 기존 40개 회귀 테스트 + 새로운 17개 획 판정 테스트.
- 전체 22,615개 기준 획의 자기 일치와 작은 위치 흔들림/이동을 가한 합성 입력 검사.
- 실제 Chromium Canvas/IndexedDB에서 터치 입력, 역방향/낙서 거부, 부분 진행 복원, 시험 재출제 검사.
- 별도 새 브라우저 컨텍스트에서 네트워크를 끄고 로컬 APK 자산 공급 방식만 허용한 첫 실행 검사.
- Android debug 빌드/정적 검사와 APK 안의 획 데이터/인터넷 권한/모델 SDK 제거 여부 검사.

이 검사는 다양한 사람의 실기기 필체에 대한 인식률 측정이 아닙니다. 물리적 Android 기기와 폰별 시스템 바/배율은 추가 점검 대상입니다. CI 실행 결과가 통과했는지 확인하기 전에는 위 목록을 모두 통과했다고 간주하지 마세요.

## 콘텐츠와 출시 제한

N5 669 / N4 655 / N3 1,798 / N2 1,844 / N1 3,485항목. 총 1,691회차입니다. 같은 어휘가 여러 급수에 있을 수 있습니다. 397항목은 한국어, 8,054항목은 영어 뜻이므로 전체 한국어 교육 검수가 아직 필요합니다. 공식 JLPT 전수 출제 목록이라고 주장하지 않습니다.

개인정보처리방침 운영자 정보, 한국어 검수, 실제 사용자 필기 테스트, 정식 서명 AAB/Play 테스트 및 심사는 미완료입니다. release 검사에 있는 미승인 항목을 검증 없이 true로 바꾸지 마세요. 내부 APK는 CI 실행마다 서명이 달라질 수 있으므로 업데이트가 거부되면 먼저 기존 기록을 백업해야 합니다.
